# 重构与现场调试交接

[English](field-debugging-guide.md)

本文档是显示统一切片和 2026-08-18 至 2026-08-20 PTB 现场调试的中文交接。它从第一次切片勘察开始，按时间追踪胶囊、历史翻译、重绘、滚动、供应商、转发消息和设置问题，并严格区分已证实根因、被推翻的假设和仍需观察的项目。

用户可见行为以 `product.md` 为准；设置归属以 `settings.md` 为准；供应商契约以 `providers.md` 为准；代码边界以 `architecture.zh-CN.md` 为准；未完成顺序以 `recovery-plan.md` 为准。

## 工作规则

1. 修改重绘原语前，先确定触发通道：实时、缓存、历史、回复预览、手动、重试和生命周期都可能产生相同闪烁。
2. 每个运行时行为变化先写失败回归测试。渲染边界单测是必要条件，但仍需要 PTB 观察。
3. 不从旧计划、截图或会话摘要推断当前行为；读取当前模块、测试、产品契约、构建 ID 和运行证据。
4. 保留原文、频道隔离、有界重试、实时优先级和单一插件产物。
5. 配置、凭证、探针 JSON、调试包、部署备份和交付目录保存在 Git 之外。
6. 重构提交只移动职责，不顺便改行为；现场修复只修改一个证实问题，不继续叠兼容补丁。

### 重构有效，但没有自动解决渲染

胶囊、输入框、翻译流水线、视口、状态、历史任务、供应商和显示逻辑已经有可测试所有者，旧运行时缩小约 19%。困难仍来自四个跨边界事实：当前函数组件没有旧方案假设的类更新器；整聊天区回退会重挂载输入框并改变虚拟列表几何；历史数据跨多个渲染 tick 到达；转发正文存在嵌套快照且 Discord 会规范化未知字段。

所以“已经模块化”不等于“现场行为已经解决”。状态、绘制、视口和状态计数都必须有单一所有者，并以真实客户端边界为证据。

## 当前显示架构

- `src/display/message-state-store.js` 负责自动/手动译文、不可变原文、回复预览、修订和恢复状态。
- `src/display/translation-display-controller.js` 提交显示事务；历史结果一次提交，回复预览宿主按波次合并。
- `src/display/flux-row-repaint.js` 通过 `MESSAGE_UPDATE` Store 合并刷新已挂载单行；`src/display/discord-render-adapter.js` 确认 DOM 修订，普通行未确认时只做有界定向重试，回复宿主仍保留独立整区回退。
- `src/orchestrator/historical-snapshot-cadence.js` 使用 500ms 安静窗口；`historical-translation-job.js` 在启动前吸收兼容任务。
- `src/viewport/message-viewport-store.js` 是阅读行锚点、用户滚动意图、底部救援、原始偏移和 180/600ms 稳定检查的唯一所有者。
- 状态胶囊由 `loaded-translation-status-store.js`、`loaded-status-capsule.js` 和 `loaded-status-position.js` 共同负责。
- 转发消息父级正文可能为空，实际正文位于 `messageSnapshots[0].message.content`；读取、显示、回声和恢复都必须使用同一组转发感知函数。

## 现场调试时间线

### 阶段 A：胶囊语义、位置和旧实例

1. 首次出现 `12/12`、`13/13` 后，后续历史批次仍重复相同分母；早期修复又出现 `0/13`、`0/47` 或 `Σ47`，都不是用户要求的累计口径。
2. 产品契约最终明确：频道级累计，分子分母都增长，例如 `13/13 → 13/33 → 33/33`；切换频道暂停/隐藏，不把数字还原成批次。
3. 调度器结果、检查数量和批次报告都曾被错误当成权威，分别造成漏记、配置上限 50 变成分母，或旧批次覆盖新累计状态。
4. 当前以消息状态存储的转换提交点记录唯一消息 ID，记录过程不刷新 DOM，批次/心跳统一显示；批次编号拒绝旧报告，已解决跳过项退出分母，失败/重试沿用累计基准。
5. 无工作扫描曾把检查数量显示为 `0/N`；现在零工作使用完成状态，`0/N` 只表示真实未解决工作或失败。
6. 每次存储提交都刷新胶囊和消息曾造成逐条翻译；静默计数和历史原子提交恢复批次表现。
7. 旧 `5/13 · 3s · Σ47` 来自停止后的热重载实例晚到回调重新创建共享 DOM；运行时活动门阻止新僵尸，已经在内存中的旧实例需要完整重启清除。
8. 胶囊曾覆盖慢速提示、超出输入框、对齐外层 wrapper、误匹配聊天正文以及因零尺寸节点瞬移。当前取最小有效提示，拒绝消息行和零矩形，固定右边缘；有提示时在其上方 8px，无提示时贴输入框上方 8px。

### 阶段 B：历史封批、重绘归因、输入框闪烁和滚动

1. 实时新消息相对稳定，但历史补翻出现逐条/小批刷新、输入框图标闪烁、滚动困难和跳到最新。
2. 同步原子重建是失败路线：未接入 React handle 时没有生效，接入后 `flushSync` 保证每个事务都重挂载，滚动更差，已经退出。
3. `rerenderAll(true)` 只合并同一 tick，不会合并几百毫秒后到达的翻译结果。
4. 先做通道归因后，现场 `other 69` 对 `hist 8` 证明回复预览回调也是重建大户，问题不只在历史正文。
5. 历史快照改为 500ms 安静窗口封批，等待任务启动前合并，恢复“一次上滚会话 → 一个任务 → 一次批次提交”。
6. 回复预览状态立即提交，但宿主重绘按 300ms 波次合并，并在用户滚动时等待。
7. 只读探针先证明公开 BDFDB dispatcher 不可用，再找到 Store dispatcher。首轮实验只证明合并安全，并未计数目标内容渲染；重开探针确认消息列表投影 `+1` 且 Composer/活动输入/目标行/Scroller 身份保持。目标译文是否可见仍由精确 DOM 修订确认；普通失败只做定向重试，回复宿主保留独立回退。
8. 用户上滚时历史显示等待滚动门；若回退重挂载把用户搁在最新消息，立即恢复可救回捕获锚点。
9. 最上方消息不是用户眼睛位置，因此锚点改为视口中心消息，并在 180/600ms 复核；任何新手势都会否决延迟写入。
10. 在旧日期开启自动翻译曾复用 4.5 秒前的手动锚点，元素被虚拟化后又缺少原始偏移回退。现在生命周期只捕获当前视口，元素缺失时先恢复偏移，再由稳定检查细化。
11. 译文增加总高度后滑块几何仍会变化；“阅读消息丢失”和“滑块移动”必须分开判断。

### 阶段 C：供应商错误和翻译完整性

1. 多个历史分块曾同时发出三条相同额度错误；现在完全相同错误在 10 秒内合并，不同错误仍显示。
2. “长消息失败”最初只是猜测，后来证实两个独立问题：CJK URL 编码长度远大于原始字符数；以及 Google 在 HTTP 200 响应中改写 `⟦N⟧` 保护标记。
3. 当前按编码后的 `q` 长度切片，尽量保留段落/句子，必要时按 Unicode code point 硬切；Google 传输使用可逆 `__DTA_N__`，切片器把完整 token 当原子。
4. 缺失、重复、乱序或损坏保护标记进入修复，不能为了“看起来成功”放松校验。
5. 主供应商额度结束后使用已配置备用供应商属于预期行为，诊断必须同时说明失败来源和完成来源，不能重复弹窗。

### 阶段 D：转发消息原文、绘制、恢复和重复原文

1. 转发消息被当成空内容，是因为父级 `content` 为空；探针证明正文位于第一份可用快照。
2. 只修提取后仍只显示原文，因为绘制仍写父级；当前克隆并修改快照，保留原型和转发引用，不原地修改 Store 对象。
3. 手动翻译、取消和关闭频道恢复曾继续读写父级；现在自动/手动统一使用快照正文访问器，恢复从已归档可见原文重建快照。
4. “一份译文 + 两份原文”和空绿色块来自父级与快照同时参与显示，且自定义身份属性被 Discord 规范化删除。
5. 当前空转发父级只负责修订确认，快照独占可见内容；关闭原文显示时一份译文，开启时译文加恰好一份引用/剧透原文，去重依据规范化后内容比较。

### 阶段 E：设置与清理

1. 译文水印死设置在切片前删除，水印固定显示。
2. 两条俄语剧透标签乱码单独修复并由测试固定。
3. “直接显示收到消息原文”与“查看译文时同时显示原文”重复，尤其让转发快照出现竞争显示分支。结构键、UI 行、文案、React 块、CSS、运行时分支和测试均已移除；旧持久化值被忽略。
4. `showOriginalMessage` 是唯一收到消息原文控制，使用引用/剧透形式。

## 被拒绝或已替代的路线

- 全文档扫描原生提示：抖动、误匹配、几何不稳定。
- 同步原子聊天区重建：保证重挂载，滚动成本更高。
- 函数组件 `forceUpdate`：当前客户端没有可用类更新器。
- 假设 `rerenderAll(true)` 合并数百毫秒后结果：只合并同一 tick。
- 一秒实时防抖：忙频道可能永远不刷新，也违反实时上限。
- 每条历史消息封批或刷新胶囊：破坏批次显示并放大重挂载。
- 在调度器结果层做累计：漏掉手动和直接存储提交。
- 用历史配置上限做分母：容量不是已发现工作。
- 为凑满配置合格数量而自动连续读取多页 Discord 历史（`8a3876b`）：用户上滚翻译原本正常，额外后台请求的现场测试出现大量错误；`e064fcd` 已恢复单次初始预取和安装构建 `d8af59cf7ce43f9c`，没有真实 fetch/store 证据和视口安全设计前不再尝试。
- 给快照加自定义身份属性：Discord 规范化会删除。
- 放松保护占位符：会静默显示损坏译文。
- 生命周期重绘复用旧手动锚点：虚拟化历史可能被搁到最新。
- 把所有跳转都归因于翻译：必须结合手势和“跳到最新”证据，原生 UI 与用户操作也能合法移动视口。
- 把公开开发者文档当作客户端重绘 API：公开 API 不暴露插件依赖的 React/虚拟列表边界，仍需受控内部适配器和现场证据。

## 开放或观察项

1. 普通消息确认失败已经退出整聊天区回退；回复宿主或生命周期设置变化仍可能产生 `R` 并刷新输入框。二者必须分别取得宿主确认与生命周期触发证据后再修改。
2. 译文增高会改变滚动条滑块；只有中心阅读消息丢失或视口搁在最新才重新开启缺陷。
3. Slice 5d 组合根提取已完成；当前约束为 3,248 行、两个模块级可变声明和 19 个紧凑延迟单例边界。后续门面缩减必须建立新的有界职责契约，不能延续已经关闭的计划。
4. 大模块和生成包体积仍是债务；只有职责契约存在后再拆分，不能只为行数拆文件。
5. 自动多页历史读取已在现场回退后暂停；正常停止时缓存落盘已完成，供应商物理取消和更大生命周期整合继续由证据触发。
